# doglife

**멍BTI** — 내 MBTI와 닮은 견종을 찾고, 그 강아지를 직접 키우는 반려견 육성 게임.

MBTI 16유형을 16개 견종에 1:1로 매칭해 결과를 보여주고, 매칭된 견종의 성향(에너지·독립성·애정도·훈련성)이 그대로 육성 게임의 초기 스탯이 됩니다. 즉 매칭 결과가 곧 "시작 빌드"입니다.

> 견종 매칭은 재미로 보는 콘텐츠이며 과학적 근거를 주장하지 않습니다.

## 현재 상태

**Phase A(온보딩 + 코어 케어 루프)가 동작합니다.** 서버 없이 브라우저에서 돌아가고 진행 상황은 로컬에 저장됩니다.

- MBTI 선택 → 견종 매칭 리빌 → 이름 짓고 키우기 시작
- 밥주기 / 산책 / 쓰다듬기 — 행동마다 쿨다운과 간식 코인 지급
- 포만감 / 애정 / 활력 게이지가 시간에 따라 감소, 견종 특성에 따라 감소 속도가 다름
- 아기 → 청소년 → 성견 3단계 성장
- 새로고침·재방문 후에도 이어서 진행

경제(상점·수집)와 소셜은 아직 없습니다. 로드맵의 Phase B·C에 해당합니다.

## 실행

```bash
npm install
npm run dev      # 개발 서버
npm run build    # 타입 검사 + 프로덕션 빌드
npm test         # 도메인 단위 테스트
```

모바일 화면(최대 폭 420px) 기준으로 만들어져 있어, 브라우저 개발자도구의 모바일 뷰에서 보는 편이 실제에 가깝습니다.

React 도입 이전의 단일 HTML 프로토타입은 `prototype/mbti-dog-match.html`에 그대로 남아 있습니다. 의존성 없이 파일을 열면 바로 뜹니다.

## 저장소 구조

```
src/domain/       게임 규칙. 순수 TypeScript — 브라우저 API를 참조하지 않는다
src/data/         저장·복원·검증. 저장소 구현 교체 지점
src/hooks/        도메인 결과를 React 상태로 배선
src/screens/      화면
src/components/   표시 전용 컴포넌트

docs/architecture.md        설계 — Phase B를 염두에 둔 구조와 Supabase 스키마 초안
docs/game-expansion-spec.md 육성 게임 확장 스펙 (원본)
prototype/                  React 이전의 단일 HTML 프로토타입
```

## 설계 요약

Phase B에서 서버를 도입할 때 게임 규칙을 두 번 쓰지 않도록, 지금부터 세 가지를 지키고 있습니다. 자세한 내용은 [`docs/architecture.md`](docs/architecture.md)에 있습니다.

1. **도메인 계층은 순수하게** — 현재 시각조차 인자로 주입받습니다. 같은 모듈을 Supabase Edge Function에서 그대로 돌려 클라이언트 결과를 재검증할 수 있습니다.
2. **게이지는 누적하지 않고 유도** — 스냅샷과 그 시각만 저장하고 현재 값은 경과 시간에서 계산합니다. 서버가 같은 값을 재현할 수 있습니다.
3. **저장소는 인터페이스 뒤에** — Phase B에서 `src/data/index.ts` 한 줄만 바꿔 Supabase 구현으로 교체합니다.

## 로드맵

`docs/game-expansion-spec.md`에 전체 내용이 있고, 요약하면 다음과 같습니다.

| 단계 | 내용 | 백엔드 | 상태 |
|---|---|---|---|
| **A** | 온보딩 + 코어 케어 루프 (밥·산책·스킨십, 스탯 감소, 성장 단계) | 불필요 (로컬 저장) | 구현됨 |
| **B** | 경제 + 수집 (간식 코인, 상점, 코스튬) | Supabase 도입, 재화 로직은 서버 검증 필수 | 설계됨 |
| **C** | 소셜 (친구, 방문, 주간 랭킹, 선물) | Supabase Auth + 랭킹 집계 | 미착수 |
| **D** | 라이브옵스 (시즌 이벤트, 신규 아이템 공급) | 상시 운영 리소스 | 미착수 |
