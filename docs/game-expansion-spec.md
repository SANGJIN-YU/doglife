# 멍BTI: 육성 게임 확장 스펙 (드래프트)

디자인 정체성(색상/타이포/톤)은 기존 멍BTI 프로토타입 그대로 계승. 멍BTI 결과는 **캐릭터 생성 시 초기 스탯 보너스**로만 사용 — 게임 코어 로직에는 관여하지 않음.

---

## 1. 스코프에 대한 솔직한 평가

"경제 + 수집 + 소셜"은 라이브 서비스형 게임의 3대 축입니다. 이게 들어가면:

- **서버가 필수**: 재화·수집 아이템은 클라이언트에만 두면 조작(치팅)이 바로 발생 → 처음부터 Supabase(또는 동급 백엔드)가 진실의 원천이어야 함
- **콘텐츠 파이프라인 필요**: 수집 요소는 "만들고 끝"이 아니라 지속적으로 새 아이템/이벤트를 공급해야 유지됨 (런칭 후에도 계속 인력 투입)
- **소셜은 인프라 비용을 동반**: 친구 목록, 랭킹, 방문 기능은 실시간/준실시간 서버 로직과 모니터링이 필요

5인 팀 기준, 이건 **1~2주 데모가 아니라 3~4개월 로드맵**으로 보는 게 맞습니다. 아래처럼 단계를 쪼개서, 각 단계 끝마다 실제로 릴리즈 가능한 상태를 만드는 걸 추천합니다.

---

## 2. 온보딩 변경: 퀴즈 → MBTI-견종 매칭

12문항 퀴즈는 제거. 대신 **사용자가 자신의 MBTI를 직접 선택 → 매칭되는 견종 공개**하는 단일 리빌 화면으로 대체 (`mbti-dog-match.html` 프로토타입 참고). 이 리빌 모먼트가 온보딩이자 공유 포인트가 됨.

16개 MBTI ↔ 16개 견종 1:1 매핑, 각 견종의 실제 성향(에너지/독립성/애정도/훈련성)을 "재미로 보는" 톤으로 제시. 과학적 근거를 주장하지 않도록 문구에 유의.

## 3. 견종 특성 → 초기 스탯 매핑

매칭된 견종의 4가지 특성치(0~100)가 그대로 게임 내 초기 스탯이 됨:

| 특성 | 게임 내 역할 |
|---|---|
| 에너지 | 산책 필요 빈도, 에너지 게이지 감소 속도 |
| 독립성 | 애정 게이지 감소 속도 (독립성 높을수록 천천히 감소) |
| 애정도 | 스킨십 시 애정 획득량 |
| 훈련성 | 훈련 미니게임 성공률 |

→ 16개 견종 = 16개의 "시작 빌드". 유형별 유불리는 있어야 게임성이 생기되, 밸런스는 알파 단계에서 조정.

---

## 4. 단계별 로드맵

### Phase A — 온보딩 + 코어 케어 루프 (4주, 로컬 우선)
- 온보딩: MBTI 선택 → 견종 매칭 리빌 화면
- 밥주기 / 산책 / 쓰다듬기 → 허기·애정·에너지 3개 스탯 (매칭 견종의 특성치가 초기값)
- 스탯 시간 경과에 따라 감소 (틱 기반)
- 성장 단계 2~3개 (아기 → 성견) — 비주얼 변화로 보상감 제공
- **아직 서버 불필요**, 로컬 저장

### Phase B — 경제 + 수집 (6주, 여기서 Supabase 도입)
- 재화(간식 코인) 획득: 케어 행동 완료 시 지급
- 상점: 코인으로 아이템/스킨/장난감 구매
- 수집: 랜덤 박스 또는 미션 보상으로 얻는 코스튬/악세서리
- **서버 권위 로직**: 재화 지급·차감은 반드시 서버(Supabase Edge Function)에서 검증 후 처리 — 클라이언트는 요청만

### Phase C — 소셜 (6주+)
- 친구 추가 / 다른 유저 강아지 방문
- 주간 랭킹(애정도, 수집 아이템 수 등 기준)
- 선물 보내기 (간식/아이템)
- 필요 인프라: 유저 인증(Supabase Auth), 친구 관계 테이블, 랭킹 집계 배치 작업

### Phase D — 라이브옵스 (지속)
- 시즌 이벤트, 신규 수집 아이템 주기 공급
- 여기부터는 "개발 완료" 개념이 아니라 상시 운영 리소스가 필요함 — 팀 구조상 이 단계까지 갈지 미리 결정 필요

## 5. 기술 스택 변경 사항 (기존 퀴즈 스펙 대비)

| 영역 | 기존(퀴즈) | 변경(게임) |
|---|---|---|
| 백엔드 | 불필요 | Supabase 필수 (Phase B부터) |
| 인증 | 없음 | Supabase Auth (Phase C부터) |
| 클라이언트-서버 신뢰 | 해당없음 | 재화/수집 로직은 반드시 서버 검증 |
| 상태관리 | 단순 context | 서버 동기화 필요 (react-query 등 고려) |

---

## 6. 다음 액션 제안

지금 결정할 건 딱 하나: **Phase A만 먼저 만들지, 처음부터 B까지 염두에 두고 설계할지**입니다. Phase A는 이전에 드린 퀴즈 스펙과 거의 동일한 난이도라 팀이 바로 시작할 수 있고, Phase B 이후는 백엔드 설계를 먼저 확정해야 착수 가능합니다.
